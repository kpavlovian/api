# Валидация данных клиента (Модуль № 4, ДЭ 09.02.07)

Клиентское Java/Swing-приложение для демонстрационного экзамена по
компетенции «Осуществление интеграции программных модулей». Приложение
получает данные клиента через API-эмулятор **TransferSimulator** и
проверяет их на корректность (в первую очередь — ФИО на вхождение
запрещённых символов).

## Возможности

- Выпадающий список выбора типа запрашиваемых данных: `fullName`,
  `snils`, `inn`, `email`, `idEntityCard` — все методы из расширенного
  описания API.
- Кнопка **«Получить данные»** — запрашивает данные с сервера (по
  умолчанию используется URL сервера лаборатории, не `localhost`).
- Кнопка **«Отправить результат теста»** — проверяет полученное
  значение и выводит результат на форму (как в макете задания).
- Поле адреса API можно менять в интерфейсе (например, чтобы
  переключиться на резервный интернет-адрес).
- Встроенная **локальная заглушка API** (чекбокс в интерфейсе) — нужна
  только для автономной отладки клиента вне сети техникума; в боевом
  режиме не используется и не подменяет собой реальный эмулятор.

## Адреса API (из `api_info.docx`)

| Окружение | URL |
|---|---|
| Лаборатория (по умолчанию) | `http://192.168.1.200:4444/TransferSimulator/` |
| Интернет (резервный, может не работать) | `http://prb.sylas.ru/TransferSimulator/` |

## Структура проекта

```
project/
├── pom.xml                          # сборка через Maven (опционально)
├── build.bat / run.bat              # сборка и запуск без Maven (javac + jar)
└── src/main/java/ru/ket/validator/
    ├── MainFrame.java               # GUI (Swing) — форма по макету задания
    ├── ApiClient.java               # HTTP-клиент к TransferSimulator API
    ├── DataType.java                # типы данных / методы API (для выпадающего списка)
    ├── DataValidator.java           # правила валидации (ФИО, СНИЛС, ИНН, email, карта)
    └── MockApiServer.java           # локальная заглушка API для отладки без лаборатории
```

Внешние зависимости не требуются — используется только стандартная
библиотека JDK 17+ (`java.net.http.HttpClient` и
`com.sun.net.httpserver.HttpServer`).

## Сборка и запуск

### Вариант 1 — IntelliJ IDEA / Eclipse (Maven)

1. Открыть папку `project` как Maven-проект.
2. Запустить `ru.ket.validator.MainFrame` (Run).
3. Либо собрать jar: `mvn clean package` → `target/DataValidatorApp.jar`.

### Вариант 2 — без Maven, из командной строки (Windows)

```bat
build.bat
run.bat
```

### Вариант 3 — вручную

```bash
javac -encoding UTF-8 -d out $(find src/main/java -name "*.java")
jar cfe DataValidatorApp.jar ru.ket.validator.MainFrame -C out .
java -jar DataValidatorApp.jar
```

## Проверка API через Bruno (перед запуском приложения)

Согласно заданию, перед разработкой клиента API нужно проверить
вручную через Bruno:

1. Взять архив с ПК преподавателя:
   `\\kab7-main\!Install_net\!programing\api\bruno_2.14.2_x64_win.zip`
2. Распаковать в `C:\Programs\API`.
3. Запустить Bruno, создать новый запрос:
   - Метод: `GET`
   - URL: `http://192.168.1.200:4444/TransferSimulator/fullName`
     (аналогично для `snils`, `inn`, `email`, `idEntityCard`)
4. Убедиться, что ответ имеет вид `{"value": "..."}`.
5. Только после этого проверять тот же запрос в собственном приложении.

Если API возвращает `HTTP 500 Internal Server Error` — это
предполагаемая ошибка сервера, а не клиента; по заданию в этом случае
нужно сразу обратиться к главному эксперту.

## Логика валидации ФИО (обязательное требование задания)

Проверяются минимум два критерия запрещённых символов:

1. **Наличие цифр** в ФИО (например, `Ива&нов 1ван 1ванович!` из
   макета задания — содержит цифры `1`).
2. **Наличие спецсимволов**, не являющихся буквой, пробелом или
   дефисом (например, `&`, `!`, `_`).

При обнаружении хотя бы одного нарушения выводится сообщение:
`ФИО содержит запрещенные символы` (текст соответствует макету формы
из задания). Дополнительно реализована упрощённая валидация СНИЛС,
ИНН, email и номера карты-пропуска — это расширяет функциональность
выпадающего списка, но не является обязательным по тексту Модуля № 4.
